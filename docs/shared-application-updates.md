`AnnieScigliano/ASCII-Interfaces`, production branch `poc/school-avatar-quest`.
The branch is the existing maintained live-workshop/handoff stream, not the old
repository default branch or arbitrary design drafts. This is an explicit source
selection; it does not authorize arbitrary repositories or all future software.

`build_workshop_release.py` compares exact original Git objects with the App's
attributed upstream/receiving inventories. It retains authenticated account

invent a resolution. Unknown model-validator changes need the compatible owning

separate. The maintainer owns the workshop geometry, artwork and local typography.

new maintainer stylesheet rules do not conflict with an appended App theme block.

redirects once to the selected generation. All relative modules and local fonts

An open editor is never reloaded or rebound by an update. Authenticated parent

A model/backend contract change cannot bypass the exact installed validator
compatibility check. Rollback selects an existing compatible code generation;
it never restores an older actor database or switches a person's saved avatar.

## One bounded existing-owner operation

Use the installed `update_shared_workshop.py --config PRIVATE.json`; the private
receiving runbook owns actual transport/config references. Register each existing
consumer's service/config and held transport, never its credentials. A new App
admission must join this inventory and receive the current component before its
workshop is advertised as current. No new identity, enrollment or Telegram is
required. This operator does not install native Core, change voice or grant new
application access.

The pinned updater installation includes the consuming web runtime, both browser
fixture files, both update scripts, shared_asset_release.py and
avatar_workshop_provenance.py. Preserve the unit WorkingDirectory so the existing
fixture resolves its synthetic import asset inside that generation. Use a short
owning data-filesystem build_root: Chromium temporary Unix socket paths must fit
the platform limit. These are code/fixture dependencies, never copies of account
state. A failed qualification produces no release activation.

The configured user timer follows the selected production branch every15minutes,
with at most30s jitter. A maintainer/operator can invoke the same oneshot for
immediate convergence. Runs are serialized, bounded to600s/1GiB/one CPU. They
fetch one selected source, compose one candidate and run the existing mounted
editor/store/Canvas/browser qualification with synthetic actors and zero providers.
A source conflict or failed qualification keeps the preceding release. Unchanged
publications reuse the admitted release and only reconcile registered consumers.
No model or private-history attention is installed.

Each actual consumer is observed, prepared and selected through its current
service UID, under a generation-fenced file CAS; native/web services are not restarted for future
frontend releases. Lost selection replies are resolved from the exact current
file after the bounded helper expires, never by replaying native input. A later
selection is preserved. Divergence after confirmed adoption is a held consumer
direction for that publication, never permission to reinstall it. Unchanged-source
checks observe the hold; a genuinely later maintainer publication is a new release.
Observation failure preserves the last confirmed adoption/direction and cannot
turn it into new admission. The exact selection generation prevents an unknown
write followed by rollback from passing an old same-release CAS. Partial consumers remain explicit. A configured
`enabled:false` is a deliberate consumer opt-out, not adoption.

The existing Alerts `scheduled_job` observer watches this timer/service's actual
finite result and cadence. Failed, disabled, stale or overlong updates produce
an operational incident through that existing service; success and human reading
remain distinct. Do not claim current receiving from a Git publication alone.

## Resource bounds and recovery

A frontend contains at most128files/4MiB, at most1MiB per file and a bounded6MiB
expanded transfer. Only expected relative asset paths are admitted; directories
are opened relative to descriptors without following symlinks. Served bytes are
hashed before response. Releases retain current/previous plus unexpired code for
at least24hours, at most16generations/64MiB. Only verified old component code can
be retired. At capacity, keep current code and report failure. Actor originals
are never cleanup candidates.

The updater retains one source cache <=64MiB, one <=4MiB build, current/previous
transfers, current/previous receipts <=64KiB each and one <=64KiB qualification
log. Temporary synthetic account/server/browser state is cleaned by the existing
fixture. Source history lives in the maintainer's repository, not an unbounded
local archive. Stop the timer to stop new checks; let/stop the one finite job via
its existing service. Inspect its retained state before resuming. Stopping this
code updater is not a global Stop and never pauses a native goal.
